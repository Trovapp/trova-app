# 작업 경험 기록 (앱)

판단이 필요했던 작업마다 문제, 고른 방법과 이유, 확인한 범위를 남긴다.
"이유"는 작업 중 사용자와 나눈 대화에서 사용자가 말한 내용을 근거로 쓴다.

---

## 2026-10-01 디자인 토큰 정리(글자 크기·간격·모서리)

### 문제와 조건
- 화면 코드에 숫자를 직접 적어 글자 크기 11가지(11~48), 모서리 8가지 이상, 간격 10가지 이상이 섞여 있었다. 숫자로 직접 적은 값은 앱 전체 639곳이었다.
- 색은 `theme.ts`에 토큰 9개가 있고 "웹 globals.css와 같은 값이어야 한다"는 규칙이 있다. 웹은 Tailwind 단계(글자 12/14/16…, 모서리 8/12/full)를 쓴다.
- 디자인 개편 순서로 토큰 정리, 온보딩, 핵심 흐름, 일정 화면을 제안했고, 사용자가 "디자인은 1번부터 진행해줘"로 토큰 정리를 먼저 골랐다.

### 범위
- 1(정의만) / 2(정의 + 기존 값 교체) / 3(2 + 웹까지) 중 **2**. 상태색과 다크 모드는 뺐다.
- 사용자가 "2번이랑 M1으로 진행해줘"로 골랐다.
- 변경이 68개 파일에 걸쳐서 세 단계로 나눴다: 공용 컴포넌트, 탭 화면 5개, 나머지 화면. 사용자가 단계마다 "2단계 진행해줘", "3단계 진행해줘"로 검토 후 진행했다.

### 선택한 방법과 이유 (비교한 대안 포함)
- 글자 단계: **M1. iOS 기본 글자 단계**(11, 12, 13, 15, 16, 17, 20, 22, 28, 34 + 예외 hero 48).
  - 비교한 대안: M2 웹 Tailwind 단계(앱에서 53곳 쓰던 13이 사라져 시각 변화가 가장 큼), M3 지금 많이 쓰는 값만 추림(기준이 "지금 쓰고 있어서"뿐이라 다시 흩어지기 쉬움).
  - 처음엔 16(callout)을 빠뜨리고 제안했다가 구현 때 넣었다(16을 쓰던 곳이 그대로 남음).
- 모서리 8, 12, 16, full(웹과 같음). 간격은 4의 배수, 가운데 값은 올림(6→8, 10→12, 14→16, 18→20). 2는 아주 좁은 간격 예외(`space.xxxs`)로 남겼다.
- 원(지름의 절반)과 알약 버튼(20)은 full로 바꿔 모양을 유지했다.
- 이유: 비교표와 함께 M1을 추천했고, 사용자가 "2번이랑 M1으로 진행해줘"로 골랐다. 사용자가 따로 밝힌 이유는 없다.

### 확인한 것
- `npm run check:tokens`(scripts/check-design-tokens.mjs): 화면 코드에 숫자로 직접 적은 글자 크기, 간격, 모서리를 찾아 실패시킨다. 경로를 주면 그 범위만 검사한다.
  - 639곳 → 412 → 285 → 0, **전체 68개 파일 통과**. 예외는 1곳(이모지 1px 기준선 보정, 이유 주석 포함).
- 규칙표대로 바꾸는 변환 스크립트를 썼고, 규칙표에 없는 값은 0곳이었다.
- 숨은 상수 3개(ErrorText 글자 13, BackButton 간격 8, ProgressHero 간격 12)는 검사에 안 잡혀서 따로 찾아 토큰에 연결했다(값은 같음).
- 타입 검사(tsc)는 단계마다 통과했다.
- 시뮬레이터 전후 캡처(사용자 계정 데이터, 보기만 함): 홈, 탭 4개, 여행 상세, 영상 결과. 깨지거나 잘린 곳은 없었다.
  - 바뀐 점: 장소 행 여백 14→16, 홈 제목 26→28(줄 높이 34→36으로 비율 유지), 결과 제목 18→17.
- 변환 중 버그 1건: 예외 주석이 JSX 태그 바깥에 `// ...`로 붙어 화면에 글자가 보일 뻔했다. style 안의 `/* */`로 옮기고 변환 스크립트도 고쳤다.

### 확인하지 않은 것
- 로그인 화면, 분석 중 화면, 새 여행, 재구성 화면은 실제 계정 상태를 바꾸지 않고는 열 수 없어 캡처하지 않았다(코드 변환과 검사만).
- 바텀시트를 연 상태, 빈 화면, 오류 화면
- 큰 글자 설정(Dynamic Type)
- 웹(trova-frontend)은 범위 밖이라 글자 단계가 앱과 다르다.

## 2026-10-01 로그인 전 온보딩 (소개 + 따라하기 데모)

### 문제와 조건
- 앱을 열면 바로 로그인 화면이라, 처음 설치한 사람이 가입 전에 앱이 하는 일을 알 수 없었다. 사용법은 로그인 뒤 홈의 "이렇게 시작해보세요" 카드(글 3줄)뿐이었다.
- 공유 시트로 링크를 받는 기능(Share Extension)이 없어서, 사용법은 "공유 → 링크 복사 → Trova에 붙여넣기"다.
- 참고 자료: 사용자가 알려준 사이트 중 ScreensDesign에서 Chrome으로 "travel onboarding"을 검색했다(Mobbin은 로그인이 필요해 보지 못함).
  - Plotline(SNS 저장 게시물을 지도·일정으로 바꾸는 앱, Trova와 콘셉트가 거의 같음): "From your feed into the real world" 한 장, 플랫폼 탭과 단계별 따라하기 데모, 가입은 맨 뒤.
  - Tripsy: 넘기는 소개 화면.
  - 유료 구간은 결제하지 않고 공개 구간만 봤다.

### 범위
- 1(소개만) / 2(소개 + 따라하기 데모) / 3(2 + 예시 결과 체험) 중 **2**. 사용자가 "2번이랑 A로 진행해줘"로 골랐다.
- 알림 권한 안내와 개인화 질문은 Trova에 해당 기능이 없어 뺐다.
- 두 단계로 나눴다: 1단계 뼈대와 소개 화면, 2단계 따라하기 데모. 사용자가 1단계 검토 뒤 "2단계 진행해줘"라고 했다.

### 선택한 방법과 이유 (비교한 대안 포함)
- **A. 로그인 전에 보여주기(Plotline 방식)**, 기기마다 한 번(expo-secure-store 플래그).
  - 비교한 대안: B 로그인 직후 첫 실행에만(가입 전에 가치를 못 보여줌), C 홈 안내 카드만 강화(움직이는 데모를 넣기 어려움).
- 그림은 참고 앱 것을 쓰지 않고 앱의 핀, 카드 모양으로 View만으로 그렸다.
- 데모는 다 볼 때까지 버튼을 막지 않는다(Plotline은 막음). 바로 넘어가려는 사람을 막을 이유가 없다고 판단했다. 사용자가 따로 정하지 않은 부분이다.
- 이유: 비교표와 함께 2 + A를 추천했고, 사용자가 그대로 골랐다. 사용자가 따로 밝힌 이유는 없다.

### 확인한 것
- tsc와 디자인 토큰 검사(72개 파일) 통과.
- 시뮬레이터: 개발 모드 미리보기 스위치(EXPO_PUBLIC_PREVIEW_ONBOARDING=1, __DEV__에서만)로 로그인한 채 확인했다.
  - 소개 화면 → 시작하기 → 데모 → 뒤로(소개로) → 다시 시작하기 → 로그인하고 시작하기(온보딩 닫힘).
  - 데모 3단계 자동 진행과 진행 막대 채움, 인스타그램/유튜브 탭 전환.
- 캡처로 찾아 고친 것:
  - 영상 카드 글자가 한 글자씩 줄바꿈됨 → 문구 단축
  - 점선이 흐림 → 진하게
  - 넓은 버튼 위 작은 원 강조가 얼룩처럼 보임 → 버튼 모양 테두리로 변경

### 확인하지 않은 것
- 실제 로그아웃 상태의 흐름(온보딩 → 로그인 → 다음 실행 때 다시 안 나옴). 다시 로그인하려면 사용자 계정 정보가 필요해 하지 않았다.
- 큰 글자 설정, 작은 화면(iPhone SE), 동작 줄이기 켠 상태
- 실제 사용자가 데모를 보고 첫 분석까지 가는지(전환율)는 측정하지 않았다.
