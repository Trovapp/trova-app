# 작업 경험 기록 (앱)

판단이 필요했던 작업마다 문제, 고른 방법과 이유, 확인한 범위를 남긴다.
"이유"는 작업 중 사용자와 나눈 대화에서 사용자가 말한 내용을 근거로 쓴다.

---

## 2026-10-01 디자인 토큰 정리(글자 크기·간격·모서리)

### 문제와 조건
- 화면 코드에 숫자를 직접 적어 글자 크기 11가지(11~48), 모서리 8가지 이상, 간격 10가지 이상이 섞여 있었다. 숫자로 직접 적은 값은 앱 전체 639곳이었다.
- 색은 `theme.ts`에 토큰 9개가 있고 "웹 globals.css와 같은 값이어야 한다"는 규칙이 있다. 웹은 Tailwind 단계(글자 12/14/16…, 모서리 8/12/full)를 쓴다.
- 디자인 개편 순서로 토큰 정리, 온보딩, 핵심 흐름, 일정 화면을 제안했고, 사용자가 "디자인은 1번부터 진행해줘"로 토큰 정리를 먼저 골랐다.

### 범위
- 1(정의만) / 2(정의 + 기존 값 교체) / 3(2 + 웹까지) 중 **2**. 상태색과 다크 모드는 뺐다.
- 사용자가 "2번이랑 M1으로 진행해줘"로 골랐다.
- 변경이 68개 파일에 걸쳐서 세 단계로 나눴다: 공용 컴포넌트, 탭 화면 5개, 나머지 화면. 사용자가 단계마다 "2단계 진행해줘", "3단계 진행해줘"로 검토 후 진행했다.

### 선택한 방법과 이유 (비교한 대안 포함)
- 글자 단계: **M1. iOS 기본 글자 단계**(11, 12, 13, 15, 16, 17, 20, 22, 28, 34 + 예외 hero 48).
  - 비교한 대안: M2 웹 Tailwind 단계(앱에서 53곳 쓰던 13이 사라져 시각 변화가 가장 큼), M3 지금 많이 쓰는 값만 추림(기준이 "지금 쓰고 있어서"뿐이라 다시 흩어지기 쉬움).
  - 처음엔 16(callout)을 빠뜨리고 제안했다가 구현 때 넣었다(16을 쓰던 곳이 그대로 남음).
- 모서리 8, 12, 16, full(웹과 같음). 간격은 4의 배수, 가운데 값은 올림(6→8, 10→12, 14→16, 18→20). 2는 아주 좁은 간격 예외(`space.xxxs`)로 남겼다.
- 원(지름의 절반)과 알약 버튼(20)은 full로 바꿔 모양을 유지했다.
- 이유: 비교표와 함께 M1을 추천했고, 사용자가 "2번이랑 M1으로 진행해줘"로 골랐다. 사용자가 따로 밝힌 이유는 없다.

### 확인한 것
- `npm run check:tokens`(scripts/check-design-tokens.mjs): 화면 코드에 숫자로 직접 적은 글자 크기, 간격, 모서리를 찾아 실패시킨다. 경로를 주면 그 범위만 검사한다.
  - 639곳 → 412 → 285 → 0, **전체 68개 파일 통과**. 예외는 1곳(이모지 1px 기준선 보정, 이유 주석 포함).
- 규칙표대로 바꾸는 변환 스크립트를 썼고, 규칙표에 없는 값은 0곳이었다.
- 숨은 상수 3개(ErrorText 글자 13, BackButton 간격 8, ProgressHero 간격 12)는 검사에 안 잡혀서 따로 찾아 토큰에 연결했다(값은 같음).
- 타입 검사(tsc)는 단계마다 통과했다.
- 시뮬레이터 전후 캡처(사용자 계정 데이터, 보기만 함): 홈, 탭 4개, 여행 상세, 영상 결과. 깨지거나 잘린 곳은 없었다.
  - 바뀐 점: 장소 행 여백 14→16, 홈 제목 26→28(줄 높이 34→36으로 비율 유지), 결과 제목 18→17.
- 변환 중 버그 1건: 예외 주석이 JSX 태그 바깥에 `// ...`로 붙어 화면에 글자가 보일 뻔했다. style 안의 `/* */`로 옮기고 변환 스크립트도 고쳤다.

### 확인하지 않은 것
- 로그인 화면, 분석 중 화면, 새 여행, 재구성 화면은 실제 계정 상태를 바꾸지 않고는 열 수 없어 캡처하지 않았다(코드 변환과 검사만).
- 바텀시트를 연 상태, 빈 화면, 오류 화면
- 큰 글자 설정(Dynamic Type)
- 웹(trova-frontend)은 범위 밖이라 글자 단계가 앱과 다르다.

## 2026-10-01 로그인 전 온보딩 (소개 + 따라하기 데모)

### 문제와 조건
- 앱을 열면 바로 로그인 화면이라, 처음 설치한 사람이 가입 전에 앱이 하는 일을 알 수 없었다. 사용법은 로그인 뒤 홈의 "이렇게 시작해보세요" 카드(글 3줄)뿐이었다.
- 공유 시트로 링크를 받는 기능(Share Extension)이 없어서, 사용법은 "공유 → 링크 복사 → Trova에 붙여넣기"다.
- 참고 자료: 사용자가 알려준 사이트 중 ScreensDesign에서 Chrome으로 "travel onboarding"을 검색했다(Mobbin은 로그인이 필요해 보지 못함).
  - Plotline(SNS 저장 게시물을 지도·일정으로 바꾸는 앱, Trova와 콘셉트가 거의 같음): "From your feed into the real world" 한 장, 플랫폼 탭과 단계별 따라하기 데모, 가입은 맨 뒤.
  - Tripsy: 넘기는 소개 화면.
  - 유료 구간은 결제하지 않고 공개 구간만 봤다.

### 범위
- 1(소개만) / 2(소개 + 따라하기 데모) / 3(2 + 예시 결과 체험) 중 **2**. 사용자가 "2번이랑 A로 진행해줘"로 골랐다.
- 알림 권한 안내와 개인화 질문은 Trova에 해당 기능이 없어 뺐다.
- 두 단계로 나눴다: 1단계 뼈대와 소개 화면, 2단계 따라하기 데모. 사용자가 1단계 검토 뒤 "2단계 진행해줘"라고 했다.

### 선택한 방법과 이유 (비교한 대안 포함)
- **A. 로그인 전에 보여주기(Plotline 방식)**, 기기마다 한 번(expo-secure-store 플래그).
  - 비교한 대안: B 로그인 직후 첫 실행에만(가입 전에 가치를 못 보여줌), C 홈 안내 카드만 강화(움직이는 데모를 넣기 어려움).
- 그림은 참고 앱 것을 쓰지 않고 앱의 핀, 카드 모양으로 View만으로 그렸다.
- 데모는 다 볼 때까지 버튼을 막지 않는다(Plotline은 막음). 바로 넘어가려는 사람을 막을 이유가 없다고 판단했다. 사용자가 따로 정하지 않은 부분이다.
- 이유: 비교표와 함께 2 + A를 추천했고, 사용자가 그대로 골랐다. 사용자가 따로 밝힌 이유는 없다.

### 확인한 것
- tsc와 디자인 토큰 검사(72개 파일) 통과.
- 시뮬레이터: 개발 모드 미리보기 스위치(EXPO_PUBLIC_PREVIEW_ONBOARDING=1, __DEV__에서만)로 로그인한 채 확인했다.
  - 소개 화면 → 시작하기 → 데모 → 뒤로(소개로) → 다시 시작하기 → 로그인하고 시작하기(온보딩 닫힘).
  - 데모 3단계 자동 진행과 진행 막대 채움, 인스타그램/유튜브 탭 전환.
- 캡처로 찾아 고친 것:
  - 영상 카드 글자가 한 글자씩 줄바꿈됨 → 문구 단축
  - 점선이 흐림 → 진하게
  - 넓은 버튼 위 작은 원 강조가 얼룩처럼 보임 → 버튼 모양 테두리로 변경

### 확인하지 않은 것
- 실제 로그아웃 상태의 흐름(온보딩 → 로그인 → 다음 실행 때 다시 안 나옴). 다시 로그인하려면 사용자 계정 정보가 필요해 하지 않았다.
- 큰 글자 설정, 작은 화면(iPhone SE), 동작 줄이기 켠 상태
- 실제 사용자가 데모를 보고 첫 분석까지 가는지(전환율)는 측정하지 않았다.

## 2026-10-01 영상 속 장소(결과 화면) 다듬기: 분류 필터 + 지도 전체 화면과 시트

### 문제와 조건
- 결과 화면의 위쪽이 제목, 일차 칩, 테두리 버튼("여행으로 만들기"), 글자 링크("동선 최적화"), 지도, 목록 순서라 주 행동이 다른 요소와 무게가 비슷했다.
- 장소마다 "다른 날로 이동 · 카카오맵 · 전화" 글자 버튼이 붙어 목록이 복잡했다.
- 분류(관광명소, 음식점 등) 데이터는 있었지만 표시하지 않았다.
- 참고: Plotline App Store 공개 스크린샷(지도 + 아래 시트, 분류 칩, 장소 카드).
  - ScreensDesign의 앱 안 화면은 유료 구간이라 보지 못했다.
  - 장소 사진(D)은 카카오에 사진 API가 없고 Google Places 사진이 유료라 비용 원칙상 보류를 제안했다.

### 범위
- 후보 A~E 중 **A(결과 화면 정리) + B(분류 표시)**. 사용자가 "A + B로 진행해줘"로 골랐다.
- 세 단계로 나눠 단계마다 검토받았다: B2, A2 구조, A2 장소 시트. 사용자가 "A2 진행해줘", "2단계 진행해줘"로 진행했다.

### 선택한 방법과 이유 (비교한 대안 포함)
- B: **B2. 분류 칩 + 필터가 목록과 지도 핀을 함께 거름.**
  - 비교한 대안: B1 표시만, B3 목록만 거름(목록과 지도가 달라 혼란).
  - 걸러도 번호는 원래 방문 순서를 유지한다.
  - 필터 중엔 순서 바꾸기를 끈다(걸러진 목록에서 끌면 서버에 보내는 칸 수가 어긋남).
- A: **A2. 지도 전체 화면 + 끌어올리는 시트(찜한 장소 화면과 같은 @gorhom/bottom-sheet) + 하단 고정 버튼.**
  - 비교한 대안: A1 지금 배치 유지하고 정리만, A3 지도와 목록 탭 전환(같이 못 봄).
  - 일정 모드에선 목록 드래그와 시트 끌기가 겹치지 않게 시트를 손잡이로만 움직인다.
- 이유: 비교표와 함께 B2 + A2를 추천했고, 사용자가 "B2 + A2로 진행해줘"로 골랐다. 사용자가 따로 밝힌 이유는 없다.

### 확인한 것
- tsc, 디자인 토큰 검사(73개 파일) 통과.
- 사용자 계정의 김해 영상 결과 화면 캡처(보기만 함):
  - 분류 칩과 "음식점" 필터, 원래 번호 5 유지, 손잡이 숨김
  - 지도 전체 화면과 시트, 고정 버튼 "만든 여행 보기 · 김해 여행"
  - 장소 시트(다른 날로 이동, 카카오맵, 전화)
- 캡처로 찾아 고친 것:
  - 분류 표시가 여행 상세 화면에도 붙을 뻔함 → `showCategory`로 켤 때만 표시
  - 고정 버튼 아래로 목록이 비침 → 버튼 배경을 화면 끝까지 채움
  - 기본 높이에서 목록이 안 보임 → 고정 버튼과 중복이던 "만든 여행" 카드 제거
- 캡처 중 앱이 한 번 꺼졌는데, 충돌 위치가 탭 자동화 도구(XCTAutomationSupport)였다. 같은 순서로 다시 열었을 때는 정상이었다.

### 확인하지 않은 것
- 시트 끌어올리기·내리기, 시트 안에서 목록 끌어 순서 바꾸기(탭 자동화로 불가, 사용자 직접 확인 필요)
- 일정 없는 영상의 "일정 짜기" 모드, "여행으로 만들기" 입력 열기(이미 만든 여행이 있는 영상만 봄)
- "다른 날로 이동" 실제 실행(사용자 데이터가 바뀌어서 누르지 않음)
- 큰 글자 설정, 작은 화면

## 2026-10-01 비서 애니메이션 이어지게(O1), 여행 상세 행 정리(T2)와 지도+시트 구조(T1)

### 문제와 조건
- 비서 대화에서 질문을 보내면 지난 답변 옆 비서가 굳고 새 줄에서 비서가 처음부터 다시 움직였다. 사용자가 시뮬레이터에서 직접 써 보고 이렇게 말했다: "1번 대화창이 끝나면 그 움직이는 애니메이션이 꺼지는데 그냥 다음 채팅에 이어지게 하는게 좋을거 같은데".
- 여행 상세는 위쪽에 날씨 확인(글자), 전체 일정 재구성(큰 테두리 버튼), 동선 최적화(글자)가 쌓였다. 장소마다 "시간 추가 · 이동수단 추가 · 메모 추가" 글자 버튼이 붙었다.

### 범위
- 사용자가 "O1이랑 T1 + T2로 진행해줘"로 골랐다. 단계는 O1 → T2 → T1이었고, 단계마다 검토 뒤 "T2 진행해줘", "T1 진행해줘"로 진행했다.

### 선택한 방법과 이유 (비교한 대안 포함)
- O1: **움직이는 비서는 하나만, 항상 최신 줄에.** 지난 답변 옆은 빈 자리만 남긴다. 점 무리의 시계를 대화 시트가 들고 새 자리의 비서에게 넘겨 박자가 끊기지 않게 했다(Orb에 `clock` 추가).
  - 비교한 대안: O2 다음 줄로 날아가듯 이동(위치 계산이 까다롭고 검증이 어려움), O3 모두 계속 움직임(산만함).
- T2: 시간·이동수단·메모 정하기를 **기존 ⋮ 메뉴 맨 위**로 모았다. 행에는 정한 값만 보인다.
  - 범위를 정할 때 "장소 시트나 ⋮ 메뉴"라고 했는데, 장소별 행동이 이미 모여 있는 ⋮ 메뉴를 내가 골랐다. 장소 정보 시트(리뷰 요약)와 역할이 섞이지 않게 하려는 이유였고, 사용자가 정한 부분은 아니다.
- T1: 영상 속 장소 화면과 같은 **지도 전체 화면 + 손잡이로만 움직이는 시트.**
  - 일차 칩에 날짜와 장소 수를 넣고 가로로 넘긴다(참고: Plotline 일정 날짜 칩).
  - 행동 셋은 한 줄 칩으로 모았다.
  - 시트 안 입력창(검색, 메모)은 키보드에 맞춰 시트가 올라가도록 BottomSheetTextInput으로 바꿨다.
- 이유: 비교표와 함께 추천했고, 사용자가 그대로 골랐다. 사용자가 밝힌 이유는 위 O1 인용뿐이다.

### 확인한 것

## 2026-10-02 빈 시간 추천이 실제 사용자에게는 한 번도 뜰 수 없었음 (Q3)

### 문제와 조건
- 비서의 빈 시간 추천이 후보 0개였다(로컬, 운영 모두).
- 원인:
  - 서버는 "앞 장소 떠나는 시간 ~ 다음 장소 도착 시간"이 30분 넘을 때만 빈 시간을 만든다.
  - 앱과 웹 어디에도 떠나는 시간을 넣는 곳이 없었다(앱 시간 편집기는 도착 시간만 저장).
  - 운영 여행 장소 24곳 중 도착 시간 2곳, 떠나는 시간 2곳(API로 넣은 시험값으로 보임).

- 서버 주석에 "임의로 시간을 추정하지 않는다"는 원칙이 있다.

### 범위
- 사용자가 "웹은 빼고 앱만 먼저 수정해줄 수 있어?"라고 했다. 앱은 웹뷰가 아니고(지도만 웹뷰), 서버가 이미 떠나는 시간을 받는 API를 갖고 있어 앱만 바꾸면 된다고 답했다.
- 방법은 G1로 진행했다. 사용자가 방법을 명시하진 않았고, 앱만 수정하자는 말에 맞는 G1을 내가 골라 진행하겠다고 밝혔다.

### 선택한 방법과 이유 (비교한 대안 포함)
- **G1. 앱에 "머무는 시간" 입력 추가.**
  - ⋮ 메뉴에 "머무는 시간 정하기"를 넣었다. 도착 시간이 없으면 도착 시간부터 정하게 한다.
  - 30분~3시간 칩으로 고르면 떠나는 시간 = 도착 + 머무는 시간으로 저장한다.
  - 도착 시간을 바꾸면 떠나는 시간도 같은 간격으로 옮긴다.
  - 행에는 "10:00–11:00 (1시간)"으로 보여준다.
  - 비교한 대안: G2 서버가 분류별 체류 시간 추정("추정하지 않는다" 원칙 변경), G3 도착 시간 간격만으로 판단(기준값을 감으로 정해야 함), G4 기능 숨기기.
- 이유: 서버 원칙을 지키면서 앱만 바꾸는 가장 작은 변경이라 추천했다. 사용자가 밝힌 이유는 "웹은 빼고 앱만 먼저"뿐이다.

### 확인한 것
- tsc, 디자인 토큰 검사(73개 파일) 통과.
- 운영 서버(Oracle) 테스트 계정에 앱과 같은 요청을 보냈다(도착 10:00 → 떠나는 11:00 → 다음 장소 도착 13:00).
  - 전: 빈 시간 없음
  - 후: 120분 빈 시간, 후보 20곳(6.4초)
  - 비서 빈 시간 추천: 후보 카드 7개(4.9초)
  - 테스트 데이터는 정리했다.

### 확인하지 않은 것
- 앱 화면에서 실제로 머무는 시간을 눌러 저장하는 동작. 시뮬레이터가 사용자 계정이라 일정이 바뀌어서 하지 않았다.
- 떠나는 시간을 지우는 방법은 없다(서버가 빈 값을 무시함).
- 도착 시간을 넣는 사용자가 적어서(24곳 중 2곳) 실제로 빈 시간이 뜨는 빈도는 낮을 것이다.
- 웹은 그대로 도착 시간만 입력된다.

## 2026-10-03 앱 본문 폰트를 Pretendard로 교체 (웹과 통일)

- 폰트 파일 크기(실측): Pretendard 3종 합계 약 4.5MB. Noto Sans KR은 굵기별 5.9MB(3종 약 17.7MB)였다.

  - 줄 높이가 낮아져 목록이 더 촘촘하다. 영상 시트 첫 높이에서 2번째 장소가 보이기 시작한다.
- 타입 검사, 디자인 토큰 검사 통과.

### 확인하지 않은 것
- 바뀐 줄 높이가 나머지 화면에 주는 영향: 찜한 장소·마이페이지·대화 시트·새 여행·재구성 화면은 보지 않았다.
- 안드로이드.
- 실제 앱 설치 파일 크기 변화: 파일 크기만 쟀다.

### 진행 중 실수
- 다섯 화면에 import를 넣는 스크립트가 기존 `MAX_FONT_SCALE`의 "FONT"를 보고 건너뛰었다. 그사이 사용자 시뮬레이터가 핫 리로드돼 오류 화면이 잠깐 떴다. import를 고친 뒤 다시 불러와져 정상 화면으로 돌아온 것을 확인했다.

## 2026-10-03 여행 이름이 안 보이고, 장소 상세 시트가 영상 시트에 겹쳐 보임 (QA A1·A2)

## 2026-10-03 조작 반응 다듬기 (QA B1~B4)

- B4: Feather `menu` 아이콘(iOS 목록 순서 바꾸기와 같은 가로줄 3개)으로 바꾸고 ⋮와 간격을 더 뒀다.

### 확인한 것 (사용자 시뮬레이터, 보기만)
- 홈 입력창을 누르면 강조색 테두리와 커서가 보인다.
- 찜한 장소 검색창이 돋보기가 있는 모양으로 보인다.
- 마이페이지 동작 행에 화살표가 없다.
- 여행 상세 장소 행에 ⋮와 ≡ 손잡이가 떨어져 보인다.
- 타입 검사, 디자인 토큰 검사 통과.

## 2026-10-07 결제됐는데 서버 기록이 실패한 패스 이어 붙이기 — 일부만 확인

### 문제
- 결제 페이지는 서버 기록이 성공해야 거래를 마무리한다(실패하면 StoreKit에 "마무리 안 됨"으로 남아 다시 시도 가능). 안내도 "앱을 다시 열면 다시 시도해요"였다.

### 한 것
- `PendingPurchaseSync`(App 최상단): 로그인 상태에서 앱이 열리거나 앞으로 돌아올 때마다 `getPendingTransactionsIOS()`로 여행 패스 거래를 찾아 서버에 기록하고, 성공한 것만 마무리한다. 실패하면 그대로 두고 다음에 다시 시도.

### 확인한 것 (Xcode StoreKit 테스트, QA 17 Pro, 로컬 서버를 테스트 거래 거절로 띄움)
